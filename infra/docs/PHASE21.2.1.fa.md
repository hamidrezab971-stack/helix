# ارزیابی HELIX Phase 21.2.1 — ۲۰ اکتبر ۲۰۲۶

**NO-GO — VERIFIED REMAINING BLOCKERS**

اصلاحات زیر در سورس پیاده‌سازی و آزمون شدند؛ image جدید ساخته یا جایگزین نشد.
این نشست به Docker socket، systemd، شبکهٔ IPv4 و ارسال روی socket محلی AF_UNIX
دسترسی ندارد. دادهٔ زندهٔ `/var/lib/helix` نیز قابل خواندن نبود. بنابراین وضعیت
healthy نشست قبلی، اسکن جدید، ورود واقعی و آمادگی cutover مجدداً تأیید نمی‌شوند.
هیچ توقف نویسنده، تغییر مسیر عمومی یا اعمال migration روی تولید انجام نشد.

۱۲۹ یافتهٔ بسته‌ای/باینری در مجموع به ۳۰ CVE یکتا مربوط‌اند. شواهد اصلی Trivy
0.76.0، زمان DB، بسته‌های نصب‌شده، fixed versionها، توضیحات و باینری‌های مربوط
بازبینی شدند. ۸۵ یافتهٔ مانیتورینگ اصلاح در سطح کتابخانه دارند؛ وجود image رسمی
اصلاح‌شده از این عدد نتیجه نمی‌شود. نسخه‌های اعلام‌شده در صفحات رسمی هنوز
Prometheus 3.13.4 LTS / 3.15.0، Grafana 13.2.4 و Node Exporter 1.12.1 بودند.
هیچ tag یا digest جدیدی حدس زده نشد و ارتقای major انجام نشد.

در لایه‌های image برنامه، `infocmp` آسیب‌پذیر و ۱۱ فایل SUID/SGID واقعاً وجود
دارند. Dockerfile اکنون infocmp را حذف و بیت‌های SUID/SGID را پاک می‌کند؛
metadata بسته‌ها برای اسکن باقی می‌ماند. اجرای این تغییر در image هنوز تأیید نشده.
`systemd-homed` و `Archive/Tar.pm` در image آرشیوشده وجود ندارند؛ یافته‌های مربوط
overmatch مؤلفه هستند. libacl و util-linux با پیش‌نیازهای محلی/دسترسی ممتاز
ارزیابی شدند، نه صرفاً با شمارش CVE. Highهای kin-openapi و مسیرهای HTTP Range
تا اثبات اصلاح یا عدم دسترسی، مانع انتشار باقی می‌مانند.

Compose برای اجرای بعدی Grafana، ۱۲ datasource backend بلااستفاده و نصب خودکار
plugin را غیرفعال می‌کند؛ datasource پرومتئوس حفظ شده است. این mitigation در
کانتینر فعال هنوز اعمال/تأیید نشده و تعداد یافته‌های اسکن را مخفی نمی‌کند.

ابزار اسکن جدید، چهار image با digest ثابت را با DB تازه و حداکثر سن ۲۴ ساعت
اسکن می‌کند؛ تمام severityها و یافته‌های بدون fix حفظ می‌شوند. اسکنر non-root،
با محدودیت منابع و بدون Docker socket اجرا می‌شود. gate روی هر High/Critical
خروجی ناموفق می‌دهد. اجرای gate روی شواهد اصلی واقعاً با exit=1 متوقف شد.
هیچ ریسک حل‌نشده‌ای برای تولید پذیرفته نشده است.

۷/۹، سرویس‌ها ۹/۹. گزارش قبلی هر query را یک پنل شمرده بود. verifier اکنون این

inventory باید روی Grafana واقعی بررسی و دامنهٔ مورد انتظار صریحاً اصلاح شود.
هیچ پنل مصنوعی برای رسیدن به عدد ۳۰ ساخته نشده است.

## تداوم داده، حساب‌ها و rollback

روی کپی دومِ snapshot واقعی موجود از ساعت ۲۰:۴۶ UTC، دو چرخهٔ startup میان سورس
کاندید و انتشار قبلی اجرا شد. هر ۲۰ جدول، ۱۳ حساب و password hashها، ۶۷ پیام،
۲۱ گفتگو، ۵ attachment، ۳ عکس پروفایل و هش هر ۸ فایل رسانه حفظ شدند؛ integrity
و foreign keys سالم ماندند. کلید JWT و کلید مؤثر CAPTCHA در حافظه با تنظیمات
فعلی تولید برابر بودند. این نتیجه، تمرین آفلاین روی backup قبلی است؛ آزمون
Docker، تغییر مسیر Nginx، نوشتن پیام جدید یا backup نهایی محسوب نمی‌شود.

**ورود یک حساب واقعی هنوز تأیید نشده است.** handoff قبلیِ credential خالی بود.
ابزار جدید `verify-retained-auth.py` از FD مهروموم‌شدهٔ مکانیزم موجود یا ورودی
مخفی در SSH پشتیبانی می‌کند؛ قبل از دریافت credential، image و mount ایزوله و
کلیدها را کنترل می‌کند. CAPTCHA واقعی، JWT و APIهای محافظت‌شده را می‌آزماید و
حفظ نام/هش حساب‌ها را بررسی می‌کند. رمز در argv، env، فایل یا log ذخیره نمی‌شود؛
proxy و redirect نیز رد می‌شوند. در این نشست credential واقعی دریافت نشد.

هش واحد systemd، فایل Nginx، release marker، تمام بایت‌های env تولید و مقصد
`/opt/helix/current` نسبت به ابتدای این نشست ثابت ماندند. PID فعال و نویسندهٔ
جاری قابل مشاهده نبودند؛ از این برابری فایل‌ها ادعای سلامت جاری ساخته نمی‌شود.
backup خارج از میزبان و اعلان بیرونی alert همچنان تأیید نشده‌اند.

مانیتورینگ قبلی مربوط به کاندید ایزوله و میزبان است؛ telemetry برنامهٔ systemd
تولید نیست. برای cutover، TSDB مستقل تولید لازم است تا تاریخچهٔ QA با نام تولید
نمایش داده نشود. volumeهای قبلی و دادهٔ Grafana باید حفظ شوند.

## ترتیب cutover پیشنهادی، بدون مجوز اجرا

۱. تأیید release عمومی و manifest جدید زیر lock موجود؛ ۲. شروع maintenance؛
۳. توقف و اثبات خروج نویسندهٔ systemd؛ ۴. backup تازه و سازگار DB/media/env؛
۵. integrity/FK/hash و تمرین restore روی کپی همان backup؛ ۶. اجرای تنها نویسندهٔ
Docker روی دادهٔ تأییدشده؛ ۷. تغییر Nginx پس از سلامت خصوصی؛ ۸. ورود واقعی و
API محافظت‌شده؛ ۹. WS/presence/attachment/history؛ ۱۰. targetها و داشبوردهای واقعی
تولید؛ ۱۱. در خطا توقف Docker و سنجش runtime قبلی روی کپی جدیدترین داده؛
۱۲. rollback روی همان دادهٔ جاری، بدون بازگرداندن backup قدیمی روی نوشته‌های جدید.

[ترتیب دقیق، مسیرها، پیش‌شرط‌ها و rollback](CUTOVER-21.2.1.md) آماده است.
manifest/guard جدید هنوز تکمیل و مهر نشده؛ **هیچ ترتیب اجراییِ production تأیید
نشده است**. برآورد قدیمی ۲–۵ دقیقه تضمین نیست؛ آزمون جدید توقف نویسنده و backup
برای تعیین پنجره لازم است. فضای دیسک این نشست حدود ۳۳ GiB و inode مصرفی حدود ۶٪
بود؛ CPU/RAM سرویس‌ها و قطعی تولید اندازه‌گیری نشدند.
